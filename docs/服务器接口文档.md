# 服务器接口文档

## 基础信息

基础地址：`https://codex.ximuai.com/api/v1`

请求和响应格式：JSON。POST 请求头：`Content-Type: application/json`。

除登录接口外，均需携带登录接口返回的令牌：

```http
Authorization: Bearer <access_token>
```

## 1. 登录

**POST `/auth/login`**

认证：无需令牌。

请求体：

```json
{
  "email": "user@example.com",
  "password": "<password>"
}
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `email` | string | 是 | 邮箱 |
| `password` | string | 是 | 密码 |

成功响应：

```json
{
  "access_token": "<access_token>"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `access_token` | string | 登录令牌 |

## 2. 获取当前账户

**GET `/auth/me`**

认证：Bearer Token。无请求参数。

成功响应：

```json
{
  "email": "user@example.com",
  "balance": 12.34
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `email` | string | 账户邮箱 |
| `balance` | number | 账户余额 |

## 3. 获取可用分组

**GET `/groups/available`**

认证：Bearer Token。无请求参数。

成功响应：

```json
[
  { "id": 7, "name": "OpenAI 分组", "platform": "openai" },
  { "id": 8, "name": "Claude 分组", "platform": "anthropic" }
]
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer | 分组 ID |
| `name` | string | 分组名称 |
| `platform` | string | 平台：`openai`、`anthropic` |

## 4. 获取分组密钥列表

**GET `/keys`**

认证：Bearer Token。

查询参数：

| 参数 | 类型 | 本项目请求值 |
| --- | --- | --- |
| `page` | integer | 页码，从 `1` 开始 |
| `page_size` | integer | 每页数量，固定 `100` |
| `group_id` | integer | 分组 ID，正整数 |

请求示例：

```http
GET /api/v1/keys?page=1&page_size=100&group_id=7
Authorization: Bearer <access_token>
```

成功响应：

```json
{
  "items": [
    {
      "id": 12,
      "key": "<api_key_secret>",
      "name": "西牧ai",
      "group_id": 7,
      "status": "active",
      "expires_at": null,
      "quota": 0,
      "quota_used": 0
    }
  ],
  "pages": 1
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `items` | ApiKey[] | 密钥列表，结构见“密钥响应字段” |
| `pages` | integer | 总页数，非负整数 |

## 5. 获取密钥详情

认证：Bearer Token。

| 路径参数 | 类型 | 说明 |
| --- | --- | --- |
| `key_id` | integer | 密钥 ID，正整数 |

成功响应：

```json
{
  "id": 12,
  "key": "<api_key_secret>",
  "name": "西牧ai",
  "group_id": 7,
  "status": "active",
  "expires_at": null,
  "quota": 0,
  "quota_used": 0
}
```

响应字段见“密钥响应字段”。

## 6. 创建密钥

**POST `/keys`**

认证：Bearer Token。

请求体：

```json
{
  "name": "西牧ai",
  "group_id": 7
}
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | string | 是 | 密钥名称，本项目传 `西牧ai` |
| `group_id` | integer | 是 | 分组 ID，正整数 |

成功响应：

```json
{
  "id": 12,
  "key": "<api_key_secret>",
  "name": "西牧ai",
  "group_id": 7,
  "status": "active",
  "expires_at": null,
  "quota": 0,
  "quota_used": 0
}
```

响应字段见“密钥响应字段”。

## 密钥响应字段

`ApiKey` 用于密钥列表、详情和创建接口的响应。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer | 密钥 ID |
| `key` | string | 密钥原文 |
| `name` | string | 密钥名称 |
| `group_id` | integer 或 null | 所属分组 ID，可省略 |
| `status` | string | 密钥状态，`active` 表示启用 |
| `expires_at` | string 或 null | RFC 3339 格式到期时间，可省略；null 表示未设置 |
| `quota` | number | 总额度，可省略，默认 `0`；`<= 0` 表示无此总额度限制 |
| `quota_used` | number | 已用额度，可省略，默认 `0` |

## 通用响应格式

上述成功示例为直接返回业务数据的格式，也兼容以下包装格式，`data` 为对应接口的成功数据：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "email": "user@example.com",
    "balance": 12.34
  }
}
```

HTTP 非 2xx 或顶层整数 `code` 非 `0` 表示失败，错误信息读取顶层 `message`：

```json
{
  "message": "<错误信息>"
}
```
